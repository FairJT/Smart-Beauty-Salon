1. SYSTEM ARCHITECTURE OVERVIEW
================================================================================

SmartSalon follows a modular monolith architecture with clean architecture principles:

┌─────────────────────────────────────────────────────────────────────┐
│                        PRESENTATION LAYER                          │
│                    (Controllers, Middleware)                        │
├─────────────────────────────────────────────────────────────────────┤
│                       APPLICATION LAYER                            │
│              (Use Cases, DTOs, Validators)                         │
├─────────────────────────────────────────────────────────────────────┤
│                        DOMAIN LAYER                                │
│           (Entities, Value Objects, Domain Events)                 │
├─────────────────────────────────────────────────────────────────────┤
│                     INFRASTRUCTURE LAYER                           │
│        (EF Core, Hangfire, External Services)                      │
└─────────────────────────────────────────────────────────────────────┘

Module Structure:
- Identity Module     -> User management, Authentication, Tenants
- Marketplace Module  -> Service Templates, Packages, Licenses
- Catalog Module      -> Salon Services Management
- Inventory Module    -> Stock Management, Movements
- Booking Module      -> Appointments, Slots, Scheduling

Shared Components:
- SalonOS.Shared      -> Money, Result, TenantEntity, Domain Events
- SalonOS.Infrastructure -> AppDbContext, Hangfire, Outbox
- SalonOS.Api         -> Program.cs, Controllers
